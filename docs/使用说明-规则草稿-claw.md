## 1. 通用：项目切换、搜索、离线（S3b、S6、S11）

**看到什么**
- 侧栏顶部是当前项目（名称 + 项目编号 code）；平台账号按经销商分组，没有经销商的集成项目归在「平台」组下；一个项目属于多个集成项目时，每个组下都会出现
- 顶栏搜索按项目名称、编号匹配，最多显示 8 条
- 平台账号在集成项目页有「经销商」可搜索下拉；经销商账号没有这个下拉

**能做什么**【操作】
- 点侧栏项目或搜索结果切换当前项目；切换会记住（浏览器本地，连同选它的账号）。同一浏览器换账号登录时不沿用上一个账号选的项目，从新账号的第一个可见项目开始；登录后也不回到上一个账号停留的页面，从首页开始（同一账号重新登录仍回原页面）（S13 走查 P7）
- 首页常用项目卡片点击直接进入该项目

**禁用 / 不生效的情况**【规则】
- 目标项目不在当前账号可见范围内：不切换，提示「项目列表正在刷新，请稍后重试」；后台刷新后仍不在范围内，提示「无权查看该项目」（判定 60 秒后过期，账号或组织数据变化时清空）
- 重复点当前项目不上报点击；首次进入时显示的"回退的第一个项目"，主动点它算一次真实选择（写入记忆并上报）
- 经销商列表加载失败：选择处显示错误和「重试」，「平台」分组仍可选

**项目离线**【操作】
- 项目离线时，传感器、温控、新风、连接状态 4 个设备页不显示旧数据，显示「项目离线，暂无数据」空态，并有「重新获取在线状态」按钮（只读，重新拉项目列表）
- 停留在离线页时每 60 秒自动重新获取一次在线状态，项目上线后自动恢复页面
- 离线横幅只写「控制屏未连接，暂时读不到设备数据，也无法下发控制。」，不显示控制屏 / DTU 编号（S13 走查 P6：control_screen_id 是型号 id、不是屏号）

**加载与无项目**【规则】
- 组织数据首次加载中、或首次加载失败：整页显示加载 / 错误，均可「退出登录」，失败页可「重试」
- 没有任何可见项目：首页、集成项目、统一控制照常进；4 个设备页显示「暂无可用项目」

**注意事项**【规则】
- 页面「退出登录」会调用 `/auth/invalidate`：同一账号在其他浏览器、其他设备、联调脚本里的登录也会一起失效，需要重新登录。测试、联调结束只清本地登录态，不要点页面上的「退出登录」
- 后端退出后旧令牌仍可用的问题已转后端处理

## 2. 首页、集成项目（S6b）

**看到什么**【操作】
- 统计卡：集成项目数、项目总数、在线、离线。优先用后端统计接口；没有该接口权限或接口失败时由前端按可见范围计算
- 前端计算时，若有项目在线状态未知：在线卡显示「≥ 已知在线数」，离线卡显示「≤ 已知离线数 + 未知数」，下方提示「数据不完整」

- 集成项目页：不再有「新建集成项目」「新建项目」「编辑」按钮（改动文档第 3、4 条）

**已知限制**
- 经销商账号目前没有 `/project/click/{id}` 权限，不上报点击，常用项目会一直为空（待后端）
- 经销商统计接口返回 3 个集成项目，实际可见 2 个（待后端）

## 3. 室内空气传感器（S8）

**看到什么**【操作】
- 实时卡片：温度、湿度、露点、PM2.5、CO₂ 等；读数为 65536（未初始化）/ -100（无效数据）的项不显示；读数 0 照常显示（0 是有效数据）；没装某种探头的项目，这一项整页不出现
- 统计区：24 小时 / 7 日 / 30 日三档，平均、最高、最低、达标率；7 日和 30 日按北京时间分天画曲线
- 达标率 = 落在标准范围内的有效小时数 ÷ 有效小时数，三档都按小时值算（Fable 裁定）。表头提示：「统计时段内，小时读数落在标准范围内的时间占比；无数据的小时不计入。」
- 标准范围（五恒指南）：湿度 40–60%、CO₂ ≤ 800 ppm、PM2.5 ≤ 35；温度冬季 18–22 ℃、夏季 24–26 ℃（5–10 月为夏季，按统计窗口结束时刻判定）。卡片上「CO₂ 超标」「PM2.5 偏高」用同一套标准
- 不再有「超标时长」「超标天数」（改动文档）
- 「导出」生成 CSV，首行写项目、传感器、时间窗口、数据时间和达标率口径

**数据不全时**【规则】
- 65536（未初始化）、-100（无效数据）算无效，不进分子分母；0 是有效数据，照常统计（后端 11/25 答复第 9 条，推翻了原来「缺字段解码出的 0 算无效」）；湿度、CO₂ 的负数也按无效处理
- 某指标统计时段内一个有效小时都没有：这一行照常显示，数值为「—」，下方灰字「有效 0/M 小时」
- 有效小时不到应有小时数一半：照常显示达标率，下方灰字「有效 N/M 小时」（M = 24 / 168 / 720，按实际窗口）
- 实时数据每 15 秒刷新；小时统计每 5 分钟刷新

**控制屏离线 / 刷新失败**【规则】
- 控制屏返回 503：显示「控制屏未连接」，不显示 503 之前的旧读数；503 后即使再遇到 500 或超时，也不恢复旧读数，直到下一次读取成功
- 503 期间实时数据降为每 60 秒探测一次，恢复后回到 15 秒
- 统计刷新失败：保留上次数据，提示「统计刷新失败，显示 HH:MM 的数据」并可「重试」；CSV 里注明数据时间

**已知限制 / 待后端**
- 已答复：0 是有效数据，-100 才是无效数据（11/25 第 9 条）
- 待后端：208 小时值是均值还是瞬时值；208 同一小时重复记录以哪条为准（目前按字段合并、多个有效值取平均）

## 4. 房间温控面板（S9）

**看到什么**【操作】
- 每个房间一张卡：开关、设定温度（− / + 步进）、节能开关、风速（只读）、末端（小标题「末端（点击选择参与运行的末端）」；风盘 / 顶辐射 / 地冷等，显示名称用 `option_name`，选中为主色实心填充、白字，未选中为白底灰描边灰字，名称后面写开 / 关（如「风盘 · 开」），前面有开（绿）/ 关（灰）小圆点；末端的开 / 关是状态显示，由控制屏自动控制，不能改，鼠标停在上面提示「开/关由控制屏自动控制」）
- 读数为 65536 / -100 的项不显示，0 照常显示；风速 0–99 为档位（0 显示「0 档」，0 档的含义待后端确认）、100 显示「自动」
- **房间开关暂时显示「开关未知」**：控制屏还没上报房间状态，读到的开关是默认值 0，不可信（后端 11/25 答复第 1 条，后端会修）。这期间开关处是「开」「关」两个按钮，顶部「已开启房间」显示 `--`；后端修好、确认读数可信后（`features.roomSwitchReported` 改成 `true`）恢复成开关
- 不再有「设定湿度」（改动文档）

**能做什么**【操作】
- 改设定温度：16–30 ℃，步长 0.5；到上下限时按钮禁用
- 开关节能
- **选择参与运行的末端**：点末端标签切换「选中 / 不选中」（鼠标停上去有手型和高亮环，改过的标签是虚线框），改动进"待下发"。可以只改末端，也可以和温度、节能一起改，同一条 201 下发
  - 至少要选一个末端：全不选时提示「至少选择一个末端」，「下发」按钮禁用
  - `is_change = false` 的末端（目前只有全空气，proto「该末端是否支持关闭」）不能改：已选中的标「不可取消」，点了只提示「「全空气」不可取消」；未选中的点了提示「不允许修改」。预检时再查一次，草稿里改了这类末端一律不发
  - 房间关着也可以改末端（规则和后端答复都没有不允许的说法，按可以处理；温度、节能仍然不能改）
  - 面板离线、项目离线、读数过期、下发进行中时末端不能点
- 开 / 关单个房间；「全部开启」「全部关闭」
- 改动先进"待下发"，点「下发」才发；可「放弃本次改动」

**每一次下发都要确认**【操作】
- 单房间设置、单房间开关、全部开 / 关都会弹确认框（负责人 11/24 决定，覆盖设计稿原说法），写明项目名、项目编号、房间和要下发的值。例：「将向 测试项目0829（240829001）的「房间11」下发「开启」指令，确定继续？」
- 点遮罩不会关闭确认框；按 Esc 或「取消」不下发

**什么时候不能改 / 不下发**【规则】
| 情况 | 表现 |
| --- | --- |
| 房间关着 | 只能开房间，温度、节能不能改。**房间开关显示「未知」时不按关着处理**，温度、节能照常能改 |
| 面板未连接、项目离线 | 都不能设置，开关也不行；提示「面板离线，不能设置」；已有的未下发修改清除并提示「已不能设置（房间关闭、面板或项目离线）」 |
| 最近一次读取失败（显示上一次的读数） | 暂时不能设置和下发，提示「面板读数暂时获取失败，恢复后可下发」；**未下发的修改保留**，下一次读取成功后照常可下发（那时再按上面的规则判断是否清除） |
| 节能开着 | 温度步进禁用，提示「节能模式下温度由系统设定」；同一次下发不能既改温度又开节能 |
| 编辑期间面板值被外部改了 | 显示冲突，不能下发，只能放弃后重新编辑 |
| 目标设备 id 在读数里缺失或重复 | 不下发，提示重新核对 |
| 确认之后重新读数，发现房间 / 开关（开关未知时不比）/ 连接 / 设定值与确认时不一致 | 不下发：「本次未下发，请重新核对后再下发」 |
| 改了末端，确认返回时或确认后新读的 200 里，末端的个数、顺序、名称、类型、`is_change`、`is_selected` 与确认时的原始读数不完全一致（末端开 / 关不比） | 不下发：「末端已在外部变化，本次未下发，请重新核对后再下发」 |
| 末端全不选 | 「下发」禁用：「至少选择一个末端」 |
| 同一控制屏上已有下发在进行（包括统一控制、别的项目、别的标签页） | 不下发：「同一控制屏上有一条下发正在进行，暂不能下发。」 |
| 写防护名单外的项目 | 不下发：「未下发：名单外」 |
| 发送前断网 / 续期失败 | 不下发：「未下发：网络中断」 |

**房间开关是否可信**【规则】
- 由测试站 `config.js` 的 `features.roomSwitchReported` 控制，默认 true（11/25 10:17 复核房间开关已真实上报）
- 设为 false 时：开关显示「开关未知」并给出开 / 关两个按钮；不拿开关禁用温度和节能；开关类下发固定判「该项暂无回读，无法确认」，2 分钟后可再操作

**下发内容**【规则】
- 201 只发改了的字段，其余不变：数值字段 -1；枚举字段用该枚举里的不变值（203 system_mode = 0）。201 全是数值字段，所以都是 -1（后端 11/25 答复第 4 条）
- 末端（end_modes）：没改末端传空列表；改了末端就把该房间全部末端完整回传（有 3 个传 3 个），只换 is_selected，末端 switch 原样带回确认后新读到的值（switch 是状态显示、不能改）（11/25 第 3 条）。只改末端时其余标量全部 -1。读不到末端（列表为空）时没有可点的末端，温度、节能照常下发
- 末端核对：改了末端时，回读 200 逐个比对 `is_selected` 和下发值（末端 switch 不比）：全部一致 → 已生效；有不一致 → 未变化；末端个数或某个位置的类型变了（无法一一对应）→ 无法核对；面板离线 → 结果未知。和温度一起改时按四态优先级合并（例如温度一致、末端不一致 → 未变化），先显示「正在核对」
- 改设定温度的确认框里加一句：「设置温度不会开启房间，房间开启后按此温度运行」
- 206 全部开关：目标房间集合取自确认后新读的完整列表，逐个核对

**下发之后**【操作】
- 先显示「已下发，正在核对…」，再根据回读显示四种结果之一（见第 7 节）
- 只有核对一致才提示「已生效」并清掉待下发的修改；其他结果下修改保留，可「放弃本次改动」或稍后「重新下发」

**已知限制 / 实测**
- 11/25 真机：201 开房间返回 success，但 3 分多钟内房间开关读数一直是 0（与 203 全开相同）。后端答复：控制屏没上报房间状态，读到的是默认值 0，房间实际是开的。这两次的「未变化」不能当作没生效，见 `docs/api/实测记录-1125-下发.md` 末尾
- 房间开关未上报期间（`roomSwitchReported = false`），开关类下发（单房间开 / 关、全部开启 / 全部关闭）的结果固定显示「该项暂无回读，无法确认」，并补一句「设备暂不回报开关状态，2 分钟后可再次操作」：核对不会一致，写锁要到 2 分钟有效期才放，这期间同一控制屏不能再下发。`roomSwitchReported` 默认 `true`（11/25 10:17 已确认房间开关真实上报），只有改回 `false` 时才是上面的情况

## 5. 新风运行设置（S10c）

只在独立空气系统（程序编码 12，测试项目 260911001）的新风页出现。其他项目（如 240829001）没有运行设置面板，也不读设置；控制屏回「该软件类型不支持此控制」时面板只写「该项目不支持新风控制」，没有下发按钮。

**看到什么**【操作】
- 右侧「运行设置」面板，逐项：开关（开 / 关）、控制类型（露点控制 / 湿度控制）、露点设定（− / +，步长 0.5 °C）、湿度设定（− / +，步长 1 %RH）、风速（低 / 高 / 自动）
- 当前控制类型对应的设定标「生效中」，另一项标「未启用」；读数上不能设置的项标锁图标「不可设置」，键盘可聚焦，提示写原因
- 改过的项在标题下写「原 X」；面板下方「待下发：风速 自动 → 高」
- 读数 -1 显示 `--`；-100、65536 显示 `--`；0 是有效值（湿度控制、风速低、开关关）

**能做什么**【操作】
- 改上面任意可改的项，改动先进「待下发」，点「下发设置」才发；可「放弃本次改动」；改回原值等于没改，没有改动时「下发设置」禁用
- 切换控制类型时，不再生效的那个设定值的改动自动去掉；改成「关」时，其他项的改动自动去掉
- 另一台设备有未下发的修改时去改这台：先确认「放弃未下发的修改」

**每一次下发都要确认**【操作】
- 确认框写明项目名、项目编号、设备和逐项「原值 → 新值」。例：「将向 独立空气系统测试（260911001）的「TXFS500」下发：风速 自动 → 高，确定继续？」
- 确认框打开期间离开页面、切项目、登出：按取消处理，不下发（见第 9 节）

**什么时候不能改 / 不下发**【规则】
| 情况 | 表现 |
| --- | --- |
| 210 某一项读到 -1 | 只禁用那一项（后端 11/25 答复第 5 条：-1 = 该项不能设置），提示「该设备的这一项不能设置」；其余项照常 |
| 控制类型读到 -1（露点与湿度均不可控） | 控制类型、露点设定、湿度设定禁用，提示「该设备当前露点与湿度均不可控，不能设置」；**风速和开关照常可设** |
| 某项读数无效（-100、65536、枚举外） | 该项禁用：「该设备的这一项没有有效读数，不能设置」；控制类型无效时露点、湿度连带禁用 |
| can_change 为假 | 控制类型不能切换：「该设备的控制类型不可切换」 |
| 露点 / 湿度二选一 | 只有当前控制类型对应的那一项能改（改了控制类型就按新类型） |
| 设备开关读数为关 | 只能改开关：「设备已关闭，请先开启再设置」；草稿里先改成开，其他项就能一起改。开关读数不可设置或无效时不按关处理 |
| 项目离线、设备未连接 | 整个面板不能下发，按钮下写原因；已有的未下发修改清除并提示一次 |
| 最近一次读取设置失败（显示上一次的读数）、读取中 | 暂时不能下发，按钮下写「运行设置读数暂时获取失败，恢复后可下发」；**未下发的修改保留**，下一次读取成功后照常可下发（那时再按本表规则判断是否清除；读数在这期间被外部改了的项按「编辑期间读数被外部改了」处理） |
| 读取失败且还没有读数、控制屏暂不可用（503） | 面板显示读取失败 / 控制屏未连接，并写「未下发的修改已保留，读取恢复后可继续下发。」；**未下发的修改保留**，恢复后同上 |
| `features.freshAirWrite = 'off'`、账号没有 204 权限 | 面板保持只读形态（只显示读数，不出现选项按钮），「下发设置」禁用并写「运行设置下发暂未开放，当前仅显示设备读到的设置」或「当前账号没有下发运行设置的权限，当前仅显示设备读到的设置」 |
| 编辑期间读数被外部改了 | 显示「…已在外部变化，未下发的修改需要重新核对」，只能「放弃修改」 |
| 确认之后重新读 202 + 210，发现设备不在 / 编号重复 / 未连接、210 读不到或不属于这台设备、任一项读数（含没改的项）与确认时不同、重新组装的内容与确认时不同 | 不下发：「TXFS500：确认后重新读取到的新风设置与确认时不一致，本次未下发，请重新核对后再下发」（按实际原因） |
| 同一控制屏上已有下发在进行（温控、统一控制、别的项目、别的标签页） | 不下发；面板下显示同屏锁提示 |
| 写防护名单外的项目 | 不下发：「未下发：名单外」 |

**下发内容**【规则】
- 只发改了的字段，其余（含没改的控制类型、露点、湿度、风速、开关）一律传 -1（后端 11/25 答复第 4 条，204 也是）
- 明确选的 0 照发：湿度控制（control_type 0）、风速低（wind_speed 0）、关（switch 0）
- id、name 取确认后新读的 210；组装只走 `buildRunningCtrlSet`，写入口编码后再查一次：不是明确改动的数值为 0 一律拒发

**下发之后**【操作】
- 先显示「已下发，正在核对…」，再根据 210 回读显示四种结果之一（见第 7 节）；只比对改了的项，没改的项读到 -1 不影响结论
- 回读到改动项为 -1 或 65536：该项「暂无回读，无法确认」；设备在 202 里未连接：「结果未知」
- 只有核对一致才提示「TXFS500 已生效：风速 高」并清掉待下发；其他结果下改动保留，可「放弃本次改动」或稍后「重新下发」
- 写锁按控制屏加：260911001 和 240829001 共用一块屏，新风下发期间 240829001 的温控、统一控制也暂停下发，最长 2 分钟

**已知限制 / 待真机**
- 204 真机实测（11/25，260911001）：风速 自动→低（0）→高→自动 三次下发均「已生效」，未改字段不变；开关机尚未真机验证
- 露点 8–16 °C、湿度 35–70 %RH 是演示版的范围（方案 A3，待后端给），界面上不写范围
- 「设备关着只能改开关」是照 201 的默认（方案 A7），待后端确认

## 6. 设备连接状态（S11）

**看到什么**【操作】
- 每台设备一行：名称、型号、地址、连接状态（在线 / 离线 / 通讯异常）；KPI 显示各状态数量与占比
- 三种状态可筛选；每 30 秒自动刷新，浏览器标签页不可见时暂停
- 「立即检测」重新读一次（检测中按钮禁用）
- 不再显示「最长离线」「丢包率」、网关 IP（接口无此字段）

**异常**【规则】
- 控制屏离线（503）：显示「控制屏未连接」，不显示旧明细；手动检测遇到 503 提示「控制屏未连接，暂时无法检测」
- 没有该接口权限：显示「未开通」，不请求
- 其他读取失败：无旧数据时显示错误和重试；有旧数据时保留并提示刷新失败

**系统设置**：没有接口支撑，入口已隐藏（Q12）；直接访问 `/settings` 回到首页

## 7. 公共规则：下发结果四态（附录）

| 结果 | 含义 | 文案 | 锁 |
| --- | --- | --- | --- |
| 已生效 | 回读读到，与下发目标一致 | 已生效 | 放开 |
| 未变化 | 回读读到，但与目标不一致。指令已下发，设备暂未变化；**不写"失败"** | 指令已下发，设备状态暂未变化 | 保持 |
| 无法核对 | 目标房间不在回读里；回包为空；该项在回读里没有对应字段；读数无效（-100 无效数据、65536 未初始化；210 里 -1 表示该项不能设置）；房间开关未上报（`roomSwitchReported = false`）时的房间开关。0 是有效读数，照常比对 | 该项暂无回读，无法确认 | 保持 |
| 结果未知 | 回读请求失败（网络、超时、非 2xx、控制屏离线），或目标面板离线 | 已下发，结果未知 | 保持 |

- 写入口返回 success 只算"已下发"，生效只认回读一致
- 首次回读不一致时先显示「正在核对…」，自动再核对（5/20/60 秒）都不一致才显示该结论；首次回读无法核对、读不到（结果未知）也一样等再核对跑完才显示（赤兔 11/25）。首次回读就一致的直接显示「已生效」。退避排不进有效期（来不及再核对）时，最后一次仍不一致就显示该结论；锁的规则不变（一致才放，否则到期）
- 多个字段时，标题取最坏的确定结论：结果未知 > 未变化 > 无法核对 > 已生效；下面逐项列出，例「1 项未生效，1 项无法核对」
- 保持锁期间按 5 秒、20 秒、60 秒自动再核对；也可手动点「核对」
- 「下发失败」只用于确定没生效的情况：控制屏回复 success=false、无权限、后端参数错误；写防护拦截、503 + code 14、未登录、发送前断网算「未下发」；超时、500、回复无法解析等都算「结果未知」，不说失败
- 下发前现查控制屏连接（ctrl 205，每次现查、单独 5 秒超时，温控 S9 与新风 S10c 共用）：第一次超时（中止那次请求、迟到的应答丢弃）自动再查一次，同样 5 秒；503、403、其他失败不重查；重查只发 205，不重发写指令（S13 走查 P2）。返回 503 就拦下，提示「控制屏未连接，暂不能下发」；两次都超时提示「控制屏在线检查超时，未下发，请重试」；其他失败（500、断网、回包解不开）提示「控制屏在线检查失败，未下发，请重试」。都算「未下发」、预检期间短暂占锁（最多 10 秒；从取锁起算，205 两次 10 秒 + 确认后读 15 秒仍在 held 30 秒内，写 12 秒应答在锁有效期内），没通过立即释放，结果条给「重试」；205 返回 403（账号无连接状态权限）同样拦下，但单独提示「当前账号无连接状态权限，无法确认控制屏在线，暂不能下发，请联系管理员」，不给重试。205 只用于提前拦截，四态判法不变。写请求收到网关纯文本 504（约 10 秒）时，结果说明加一句「控制屏 10 秒内没有应答，可能离线」（赤兔 11/25）

## 8. 公共规则：写锁（附录）

- **按控制屏加锁**：同一块控制屏上同时只允许一条下发。两个测试项目 260911001、240829001 共用一块屏，任一项目下发时另一个的温控、新风、统一控制也会被锁
- **放锁**：所有目标字段回读一致即放；否则锁到有效期到期（从发出起 2 分钟，不续期），到期后页面自动重读
- **原写还在路上不放锁**；结果未知、未变化、无法核对都不提前放
- **刷新页面、另开标签页**：结果未知的锁存在浏览器里，刷新后锁还在，会自动核对一次；别的标签页的锁同步过来，只用来拦截和提示，本标签不核对、不放
- **别的账号**看到的锁只有泛化提示：「上一账号的下发结果未知，请稍后再试或联系有权限的账号」，不显示项目名和目标值
- **只防误操作，不防越权**；越权由后端拦截
- 已知限制：跨标签页同步不是严格原子；刷新时已过期的记录直接丢弃

## 9. 公共规则：确认弹窗（附录）

- 所有下发（温控、新风、统一控制）都先弹确认；点遮罩不关闭
- 确认框打开期间下面这些情况发生，确认会**自动作废、按取消处理**，提示「页面已变化，操作已取消」：
  - 离开页面、浏览器后退 / 前进、同一页面改了查询参数
  - 当前项目切换、项目变离线（页面卸载）
  - 登出、会话过期、换账号（会话类不弹提示，避免和「登录已过期」重复）
- 确认后到真正发出之间还会再查一次：会话、项目、页面是否还在，以及同屏锁；任何一项不对都不发
- 写请求遇到 401 不重放

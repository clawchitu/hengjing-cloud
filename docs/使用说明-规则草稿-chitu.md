## 1. 登录与会话（S5）

### 1.1 平台账号和经销商账号

**【现场】**
- 登录后系统读取当前账号信息，账号类型为 1 的是经销商账号，其余（0 或缺失）按平台账号处理；平台账号在界面上显示为「管理员」，经销商账号显示「经销商」
- 平台账号能看到多个经销商的项目，统一控制、集成项目页顶部有「经销商」下拉；经销商账号只看自己名下的项目，没有这个下拉
- 能看哪些页面、调哪些接口，由后端按账号权限决定；前端的菜单只是按权限显示，不是安全边界

**【内部】**
- 账号身份、经销商标记、权限列表只放内存，不写浏览器存储，不能靠改存储伪造角色
- 经销商账号当前缺的接口权限见 Claw 那份第 2 节的已知限制

### 1.2 令牌有效期与自动续期

**【现场】**
- 登录有效期 2 小时。快到期时系统自动续期，不用手动操作
- 续期失败（令牌被拒、被别处登录挤掉等），页面提示「登录已过期，请重新登录」并回到登录页
- 切回浏览器标签页、网络恢复时会补查一次，休眠后回来也不会停在过期状态

**【内部】**
- 令牌有效期取登录接口返回的 `expires_in`，缺失按 7200 秒；到期前 60 秒（`REFRESH_LEEWAY_MS`）进入续期窗口，定时器多留 5 秒，保证触发时已在窗口内
- 续期每次换新的 refresh 令牌，旧的立即作废，所以同一时刻只能有一个续期在跑（页内单飞，多标签页用 Web Locks 互斥，BroadcastChannel 通知其他标签页换新令牌）
- 普通读请求遇到 401（code 16）或网关 403 `token err`：续期一次、重放一次；再失败就清登录态并通知过期。重放绑定发起时的账号：期间换了账号，不用新账号的令牌重放旧请求
- 读写不同：**写请求遇到 401 不重放**，见 2.7

### 1.3 登录后回到原来那一页

**【现场】**
- 没登录或登录过期时被送到登录页；重新登录后回到离开时的那一页（含查询参数），不是一律回首页
- 直接打开登录页登录，进首页

**【内部】**
- 只接受站内绝对路径：不是 `/` 开头、`//` 开头（协议相对地址）、含反斜杠或控制字符、或指向 `/login` 本身的，一律回首页（`safeFrom`）

### 1.4 同一账号在别处登录

**【现场】**
- 同一个账号在别处（另一台电脑、另一个浏览器）再登录，这里的登录会被挤掉：这边最迟在当前令牌到期、续期时被拒，提示「登录已过期，请重新登录」，需要重新登录。当前令牌过期前，已有的页面还能继续读数据
- 同一个浏览器的多个标签页共用登录：一个标签页退出，其他标签页也回登录页；一个标签页换了别的账号登录，其他标签页会重新确认身份，不会出现「旧账号界面 + 新账号令牌」

**【内部】**
- 依据 `docs/api/实测记录-1124.md`：每个用户只有一个有效 refresh 令牌，新登录让旧会话的 refresh 失效；旧会话的 access 在过期前仍可用，最迟约 2 小时被踢
- 前端没有「被挤掉」的专用提示，表现就是续期被拒后的通用过期提示；是否允许多处同时登录属后端策略，待后端确认

## 2. 统一控制（S12）

### 2.1 能看什么、能操作什么

**【现场】**
- 选项目：先选集成项目（平台账号先选经销商），列表里勾选要下发的在线项目，可按名称检索、「全选在线项目」；离线项目显示「离线 · 不可下发」，不能勾选
- 设置四项，选「不变」的不会下发：
  - 系统开关：开启 / 关闭 / 不变
  - 运行模式：夏季、冬季、通风、除湿等 14 种，加「不变」
  - 房间开关：全部开启 / 全部关闭 / 不变
  - 房间温度设定：16–30 ℃，步长 0.5，默认勾着「保持不变」，要设温度先取消勾选
- 右侧「指令预览」列出这次要下发的内容，并提示「将覆盖所选项目内用户的本地设置，请谨慎操作」
- 下方「最近一次执行结果」只有项目、项目 ID、状态、操作时间四列；「下发核对」默认收起，展开看原因、逐字段结果和下发前后的回读

**【现场】什么时候弹确认**
- 每次点「确认下发」都弹确认框，标题「确认下发统一控制指令」，写明要下发的项目数、每一项的值、项目名单，以及「下发前后各读一次当前状态用于核对；失败不会自动重试」
- 点遮罩不关闭；取消则不下发

**【内部】**
- 每个项目按顺序逐个下发，不重试；下发前先读一次当前状态，下发后再读一次核对
- 确认后、整批开始前强制重新拉一次项目列表（每批一次），发送前复核用这份最新数据；拉取失败整批不下发：「确认后刷新项目在线状态失败，整批未下发」

### 2.2 什么时候不下发或被禁用

| 情况 | 表现 | 类别 |
| --- | --- | --- |
| 项目离线 | 列表里不能勾选；已勾选后才离线的，下发时被拦：「项目离线，不能下发」（发送前复核也会拦，结果记「失败（未执行）」） | 现场 |
| app_code 为 12（独立空气系统）或 8（空气系统单机版） | 温度设定禁用，提示「该应用类型不支持温度设定，房间开关仍可下发」；app_code 缺失或不是 1 也按不可用处理：「应用类型未知，温度设定不可用」。只有 1（通用版）可设温度；12 的项目在列表里标「新风单机版」 | 现场 |
| 房间全关 | 已选在线项目里有任一个房间全部关着，温度设定禁用，提示「房间都关着（项目名），不能设定温度；需要时同时选「全部开启」」；读取房间状态期间先禁用，提示「正在读取房间状态…」。选了「全部开启」则放开；选了「全部关闭」也不能同时设温度 | 现场 |
| 选了「保持不变」 | 温度这一项不下发（预览显示「不变」）。取消勾选才能调温度 | 现场 |
| 同一块屏被锁 | 下发按钮置灰，提示「上一条下发还在处理中（项目名），请等结果确认后再下发」 | 现场 |
| 别的账号占着锁 | 下发按钮置灰，提示「上一账号的下发结果未知，请稍后再试或联系有权限的账号」，不显示项目名和目标值 | 现场 |
| 登录状态异常 | 令牌解析不出账号：不下发，「登录状态异常，请重新登录后下发」，记失败（未执行） | 现场 |
| 没有要下发的设置 | 四项全是「不变」：「没有要下发的设置」 | 现场 |
| 下发前读到房间全关又要设温度 | 发送时再拦一次：「下发前读到房间都关着，不能设定温度，未下发」 | 内部 |
| 登录账号变了 | 确认到发送之间换了账号：「登录账号已变化，未下发」 | 内部 |
| 发送前复核不过 | 页面已离开、项目换了、项目 code 变了、已离线：「发送前复核未通过，未下发」 | 内部 |

**【内部】**
- 温度可用性是白名单：`TEMP_ENABLED_APP_CODES = [1]`，8、12 明确禁用，其他一律不可用（宁可少开不误开）；房间开关不受 app_code 影响
- 温度范围当前写死 16 / 30 / 0.5，后端以后在接口里给范围，缺失时回退到这个默认值
- 一批里任何一个项目校验不过，整批不下发，错误里带项目名

### 2.3 下发结果四态与文案

**【现场】** 每个项目一行状态，四种结果：

| 结果 | 含义 | 文案 |
| --- | --- | --- |
| 已生效 | 下发后读到，与目标一致 | 已生效 |
| 未变化 | 读到了但与目标不一致，指令已下发、设备暂未变化，不写「失败」 | 指令已下发，设备状态暂未变化 |
| 无法核对 | 房间没有回读条目、回包为空、设备没回报该项、该项在回读里没有对应字段 | 该项暂无回读，无法确认 |
| 结果未知 | 回读请求失败，或目标房间有离线 | 已下发，结果未知 |

- 下发过程中先显示「正在下发…」，控制屏应答后显示「已下发，正在核对…」
- 全部项目都已生效才弹「已生效（N 个项目）」；否则汇总成「已生效 2 个，未变化 1 个，结果未知 1 个…。请稍后刷新确认，未自动重试」
- 下发前就被拦的显示「未下发」；确定没生效（控制屏回复失败）才显示「失败」，确定没执行的显示「失败（未执行）」

**【内部】**
- 控制屏返回 success=true 只算「已下发」，生效只认回读一致
- 混合字段整体排序：结果未知 > 未变化 > 无法核对 > 已生效；标题是同一种结果就写那个词，混合写计数，如「1 项未生效，1 项无法核对」（计数里未变化写作「未生效」）
- 房间开关、房间温度逐房间核对，温度按 0.01 容差；系统开关、运行模式在 200 回读里没有对应读数，一律无法核对
- 有房间离线时读数不可信，整体算结果未知

### 2.4 逐字段明细

**【现场】**
- 展开「下发核对」，每个项目先写标题（单一结果或混合计数），再逐项列出系统开关、运行模式、房间开关、房间温度，只列这次下发了的项，每项一个状态标签：已生效 / 未变化 / 无法核对 / 结果未知
- 不一致的会写明「下发 X，回读 Y」；只有部分房间不一致时标注「（N 个房间中 M 个）」；设备没回报的写「设备未回报，无法核对」，回读不到的写「无法回读（未核对）」
- 最后一行是下发前后的回读：「房间开 · 26.0°C」这样的摘要，并写明「未自动重试，请核对设备状态后再决定是否重新下发」

**【内部】**
- 回读失败时每项都是结果未知，不再列逐项的「设备未回报」；应答本身结果未知（超时、断网）时，除已回读一致的项外一律结果未知
- 结果卡片和「下发核对」存在本标签页（sessionStorage），按数据源和账号分开，换账号看不到上一个账号的结果；统一控制 203 没有可查的历史记录

### 2.5 写锁

**【现场】**
- 写锁按控制屏加：同一块控制屏上同一时间只允许一条下发，其他项目共用这块屏的，温控、新风、统一控制都会被锁
- 锁 2 分钟到期，从发出时算起，不续期；到期后页面自动重读房间状态
- 刷新页面后锁还在；结果未知的锁会在刷新后自动核对一次

**【内部】**
- 默认有效期 `DEFAULT_TTL_MS` = 2 分钟，最小 30 秒；一致才提前放；未变化、无法核对、结果未知都不提前放
- 核对不一致时在有效期内按 5 秒、20 秒、60 秒自动再核对，也可手动核对
- 锁存在 localStorage（前缀 `hjc-write-lock:`），其他标签页同步过来只用于拦截和提示；别的账号只显示泛化提示，不带项目名
- 加锁目标是控制屏号、DTU 号、项目 id；只防误操作，不防越权，越权由后端拦截
- 详见 Claw 那份第 7 节

### 2.6 35 秒截止

**【现场】**
- 一次批量下发从开始起最多 35 秒必须给出最终结果，不会一直转圈
- 到 35 秒时：还没发出的项目记「未下发（超时）」，之后不会再发；已发出但没应答或没核对完的记「已下发，结果未知」，页面不再等，不自动重试，请稍后刷新确认

**【内部】**
- `BATCH_DEADLINE_MS = 35_000`，截止后 `beforeSend` 一律拒绝
- 截止只影响界面标注；写锁不在这里放，仍按原写结算、回读核对或有效期到期
- 截止文案：「超过 35 秒截止时间，未下发（超时）」「已下发，结果未知：超过 35 秒截止时间仍未收到应答，请刷新查看；未自动重试」「已下发，结果未知：下发后回读在 35 秒截止前未完成，请稍后刷新确认；未自动重试」；控制屏明确拒绝但回读未完成的：「控制屏明确拒绝（未自动重试）；下发后回读在 35 秒截止前未完成」

### 2.7 写请求遇到 401 不重放

**【现场】**
- 下发时登录状态正好失效，会提示「登录状态已更新，请重新下发」，这条没有执行，重新登录或稍后再点下发即可

**【内部】**
- 读请求 401 走续期加重放；写请求发送前先确保令牌有效，收到 401（或 403 `token err`）直接结束这次下发，抛 unauthenticated 且不带 status（确定没执行），只在后台续期一次，绝不重放
- 真正调用 fetch 前同步复核一次：取消信号、令牌账号与发起时账号一致、令牌解析得出账号，再执行调用方的 `beforeSend`
- 控制屏未连接（503 code 14）：「控制屏未连接，未下发」；超时、断网：「未收到控制屏应答，下发结果未知」「后端连接失败，下发结果未知」「网络中断，下发结果未知」

## 3. 部署与环境

**【现场】**
- 测试站 **hvac-demo**：接真实接口（测试环境），页面请求都走本站 `/api` 转发，没有演示账号
- 演示站 **hvac-mock**：演示数据，不连任何真实接口，只有两个演示账号
- 正式交付给对方的部署包，默认不能做任何下发操作；开放下发需要负责人书面确认

**【内部】**
- 两个站共用一份构建和 `worker/index.js`，由 `wrangler.toml` 的 `DATA_SOURCE` 区分：默认环境 `real`（hvac-demo），`env.mock`（hvac-mock）。部署：`npx wrangler deploy` / `npx wrangler deploy --env mock`
- hvac-demo：`/api/*` 转发到固定上游 `API_UPSTREAM`，上游只允许 `ALLOWED_UPSTREAMS` 里的测试环境地址，否则 `/api` 一律 500；`/config.js` 由 Worker 生成（`apiBase=/api`、`apiEnv=test`、`dataSource=real`）
- 转发规则：只允许 GET / HEAD / POST；只转 Authorization 和 Content-Type 与请求体；路径只许 `[A-Za-z0-9._~/-]`，出现 `%`、空段、`.`、`..` 段都拒绝；跨站请求拒绝；不跟随重定向；去掉上游的 Set-Cookie、CORS 头、Location 和指纹头；超时 20 秒返回 504
- hvac-mock：`/api/login` 校验两个演示账号，不转发其他请求，其余 `/api` 返回 404；密码是 Worker 密钥，不进仓库
- 正式交付包用 `scripts/build-prod.sh` 打（只构建打包，不部署、不连接任何接口）：
  - `API_BASE` 只允许两个值，逐字比较，不做任何规范化：`https://control.cosyhome.com.cn/v1`（默认，直连生产接口）和 `/api`（同源，对方 nginx 反向代理）；其他一律报错退出，设成空串也报错
  - 生成的 `config.js` 写死 `writeMode: 'off'`、`writeProjectCodes: []`、`apiEnv: 'prod'`、`dataSource: 'real'`，即默认禁止一切下发；构建期默认值同样按生产写死
  - 交付模式构建剔除演示数据和演示账号；打包后解开 zip 自检：config.js 字段、index.html 加载顺序、演示特征串，任一不过就删掉半成品
  - 开放下发须负责人书面确认，由对方运维按 `docs/部署说明.md` 修改 config.js
- 下发防护的规则（`src/api/guard.ts`）：`writeMode='off'` 全部拦截；默认 `test-only` 只在测试环境放行；生产需显式 `on`；任何环境都要项目 code 在白名单 `writeProjectCodes` 里，名单为空拒绝所有写操作；判断不出环境按生产处理

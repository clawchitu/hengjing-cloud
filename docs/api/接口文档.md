# 项目 / 经销商 / 天气 接口（前端对接）

## 1. 通用约定

- 所有接口均为 `POST`，body 为 JSON（字段名 camelCase 或 snake_case 均可，响应为 snake_case，前端用 `camelcaseKeys` 转换后 `fromObject`）。
- 需要登录（Authorization 头）。
- 分页参数 `page_options`（`shared.v1.PageOptions`），响应 `total` 为总数。
- `online`（在线）由服务端实时补充：根据控制屏流（ctrlcb）与 DTU 在线设备（tsdw）计算。

## 3. GetWeather

获取城市实时天气与 3 天预报。

请求：

| 字段   | 类型   | 说明   |
| ------ | ------ | ------ |
| `city` | string | 城市名 |

响应：`{ weather: ShowAPIResBody }`

`ShowAPIResBody`：

| 字段               | 类型            | 说明                   |
| ------------------ | --------------- | ---------------------- |
| `time`             | string          | 数据时间               |
| `cityInfo`         | CityInfo        | 城市信息               |
| `f1` / `f2` / `f3` | WeatherForecast | 今天 / 明天 / 后天预报 |
| `now`              | WeatherNow      | 实时天气               |
| `remark`           | string          | 备注                   |
| `ret_code`         | int32           | 返回码                 |
| `solar_radiation`  | float           | 太阳辐射               |

`CityInfo`：`c1` 城市代码，`c3` 城市名称，`c5` 区域名称，`c7` 地区名称，`c9` 国家，`c17` 时区，`longitude` 经度，`latitude` 纬度（c0~c16 其余为区号、拼音、邮编等）。

`WeatherForecast`：

| 字段                                            | 说明            |
| ----------------------------------------------- | --------------- |
| `day` / `weekday`                               | 日期 / 星期     |
| `day_weather` / `night_weather`                 | 白天 / 夜间天气 |
| `day_weather_code` / `night_weather_code`       | 天气代码        |
| `day_weather_pic` / `night_weather_pic`         | 天气图标 URL    |
| `day_wind_direction` / `night_wind_direction`   | 风向            |
| `day_wind_power` / `night_wind_power`           | 风力            |
| `day_air_temperature` / `night_air_temperature` | 白天 / 夜间温度 |
| `air_press`                                     | 气压            |
| `jiangshui`                                     | 降水概率        |
| `ziwaixian`                                     | 紫外线          |
| `sun_begin_end`                                 | 日出日落        |

`WeatherNow`：`temperature` 温度，`weather` 天气，`weather_code`，`weather_pic`，`wind_direction`，`wind_power`，`temperature_time` 更新时间，`rain` 降雨，`sd` 湿度，`aqiDetail`（空气质量：`quality`、`aqi`、`pm10`、`pm2_5`、`co`、`o3`、`no2`、`so2`、`primary_pollutant` 等，均为 string）。

## 5. GetFrequentProjects（常用项目）

返回当前用户点击次数最多的项目，用于首页 / 快速切换。需配合 `RecordProjectClick` 在切换项目时上报。

请求：

| 字段    | 类型  | 说明                     |
| ------- | ----- | ------------------------ |
| `limit` | int32 | 返回数量，`<=0` 时默认 4 |

响应：与 `GetProjectsResponse` 相同（`project_entities`、`total`），按点击次数降序，包含 `online`。

配套 `RecordProjectClick`：`POST /v1/project/click/{id}`，body `{}`，无返回内容。

```ts
await recordProjectClick(projectId); // 切换项目时调用
const { data } = await getFrequentProjects(4);
```

## 9. 登录认证（auth）

### 9.1 Login

`POST /v1/auth/login`，无需 Authorization。

请求：

| 字段       | 类型   | 说明                                                   |
| ---------- | ------ | ------------------------------------------------------ |
| `mobile`   | string | 手机号（yaml 约定登录使用）                            |
| `username` | string | 用户名（proto 保留字段，前端一般用 `mobile`）          |
| `password` | string | 密码                                                   |
| `isdp`     | bool   | 是否登录数据平台；为 true 时，无集成功能的账号会被拒绝 |

响应 `LoginResponse`：

| 字段            | 类型   | 说明                                  |
| --------------- | ------ | ------------------------------------- |
| `access_token`  | string | 访问令牌，后续请求放 Authorization 头 |
| `refresh_token` | string | 刷新令牌                              |
| `expires_in`    | int32  | access_token 有效期（秒）             |

### 9.2 RefreshToken

`POST /v1/auth/refresh`，无需 Authorization。access_token 过期时用 refresh_token 换新令牌。

请求：`{ refresh_token: string }`

响应：`{ access_token, expires_in, refresh_token }`（返回新的 `refresh_token`，需替换本地保存的旧值）。

### 9.3 InvalidateRefreshToken

`POST /v1/auth/invalidate`，使指定用户的 refresh_token 失效（退出登录 / 踢下线）。

请求：`{ user_id: string }`；响应：空。

## 10. GetWeather24（24 小时天气预报）

`POST /v1/weather24`，数据来自第三方 showapi，服务端按请求的 `city` 缓存 30 分钟。

请求：

| 字段   | 类型   | 说明                          |
| ------ | ------ | ----------------------------- |
| `city` | string | 城市名或城市 code（不能为空） |

响应：`{ weather: ShowAPIResBody24 }`

`ShowAPIResBody24`：

| 字段       | 类型          | 说明             |
| ---------- | ------------- | ---------------- |
| `ret_code` | int32         | 0 成功，其他失败 |
| `area`     | string        | 查到的地区名     |
| `areaid`   | string        | 地区 id          |
| `areaCode` | string        | 地区 code        |
| `hourList` | HourWeather[] | 24 小时预报列表  |

`HourWeather`：

| 字段             | 类型   | 说明                         |
| ---------------- | ------ | ---------------------------- |
| `time`           | string | 时间，如 `201611061000`      |
| `weather`        | string | 天气                         |
| `weather_code`   | string | 天气代号                     |
| `temperature`    | string | 气温                         |
| `wind_direction` | string | 风向                         |
| `wind_power`     | string | 风力，如 `4-5级 8.0~10.7m/s` |

注意：`hourList`、`areaid`、`areaCode` 字段名为驼峰，与其余 snake_case 字段混用，前端若使用 `camelcaseKeys` 转换后需按 `hourList`、`areaId`、`areaCode`、`weatherCode`、`windDirection`、`windPower` 读取。

## 11. 批量统一控制（UnifiedCtrlsSend / GetUnifiedCtrlsRecords）

对多个项目同时下发统一控制（消息类型 203 `UnifiedCtrlSet`），下发后立即返回，各项目的执行结果异步记录，通过记录查询接口获取。前端函数在 `services/business/device.ts`。

### 11.1 UnifiedCtrlsSend（批量下发）

`POST /v1/ctrl/unified-ctrls-send`，前端函数 `sendUnifiedCtrls`。

请求：

| 字段          | 类型     | 说明                                                        |
| ------------- | -------- | ----------------------------------------------------------- |
| `project_ids` | string[] | 项目 ID 列表（自动去重，不能为空）                          |
| `body`        | string   | `UnifiedCtrlSetQuery` 序列化后的 base64（函数内已自动编码） |

`UnifiedCtrlSetQuery`：

| 字段            | 类型  | 说明                                                                                                                                                             |
| --------------- | ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `system_switch` | int32 | 系统开关：-1 不变，1 开启，0 关闭                                                                                                                                |
| `system_mode`   | enum  | 运行模式：0 不变，2 夏季，3 冬季，4 通风，5 除湿，6 免费制冷，8 制热除湿，9 供热，10 供热加湿，11 加湿，12 供冷，13 供冷加湿，14 供冷除湿，15 冷热过渡，100 自动 |
| `room_switch`   | int32 | 房间开关：-1 不变，1 开启，0 关闭                                                                                                                                |
| `room_temp`     | float | 房间温度：-1 不变，其他为设定温度                                                                                                                                |

响应：

| 字段       | 类型   | 说明             |
| ---------- | ------ | ---------------- |
| `batch_id` | string | 本次下发的批次号 |
| `total`    | int32  | 下发的项目总数   |

说明：

- 操作人取自登录用户，前端无需也不能传 `user_id`。
- 控制屏未连接或消息发送失败的项目，直接记为"失败"；其余项目等待控制屏回调。
- 30 秒内未收到控制屏回调的项目记为"超时"。
- 回调中 `UnifiedCtrlSetReply.success` 为 true 记"成功"，否则记"失败"，`msg` 保存到记录的 `message`。

### 11.2 GetUnifiedCtrlsRecords（查询执行记录）

`POST /v1/ctrl/unified-ctrls-records`，前端函数 `getUnifiedCtrlsRecords`（返回 `{ data, total, success }`，可直接用于 ProTable）。结果按创建时间倒序。

请求（均可选）：

| 字段           | 类型        | 说明                                                 |
| -------------- | ----------- | ---------------------------------------------------- |
| `page_options` | PageOptions | 分页                                                 |
| `batch_id`     | string      | 批次号（查某次下发的全部项目结果）                   |
| `project_id`   | string      | 项目 ID                                              |
| `project_name` | string      | 项目名称（模糊匹配）                                 |
| `project_code` | string      | 项目编码                                             |
| `result`       | int32       | 结果过滤：0 不过滤，1 等待中，2 成功，3 失败，4 超时 |
| `operator_id`  | string      | 操作人 ID                                            |
| `start_time`   | int64       | 操作时间起（unix 秒），0 不限                        |
| `end_time`     | int64       | 操作时间止（unix 秒），0 不限                        |

响应：`{ records: UnifiedCtrlsRecord[], total: int64 }`

`UnifiedCtrlsRecord`：

| 字段            | 类型   | 说明                             |
| --------------- | ------ | -------------------------------- |
| `id`            | string | 记录 ID                          |
| `batch_id`      | string | 批次号                           |
| `project_id`    | string | 项目 ID                          |
| `project_name`  | string | 项目名称                         |
| `project_code`  | string | 项目编码                         |
| `result`        | enum   | 1 等待中，2 成功，3 失败，4 超时 |
| `message`       | string | 失败原因或控制屏返回的 msg       |
| `operate_time`  | string | 操作时间，`yyyy-MM-dd HH:mm:ss`  |
| `operator_id`   | string | 操作人 ID                        |
| `operator_name` | string | 操作人名称                       |

示例：

```ts
const { batchId } = await sendUnifiedCtrls({
  projectIds: ['...'],
```

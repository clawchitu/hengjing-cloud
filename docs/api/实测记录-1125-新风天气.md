## 后端答复后的结论（11/25 08:56）

1. 疑问 1（`control_type = 0` 但 `humidity_set = -1`）：后端答复第 5 条，210 读到 -1 表示这一项不能设置（模拟新风机的模式不对造成的），前端把这一项限制成不能设置。所以这台设备只是「湿度设定」不能设置，其余项照常；上面第 3 点「现在任何 204 都会被拦下」不再成立：Fable 11/25「没改的字段读到 -1 就整条不发」的裁定被后端答复推翻，204 不变的字段一律传 -1（第 4 条），W1（只改风速）可以做。
2. 疑问 2（210 / 202 开关是关，202 却在制热、有压缩机频率）：第 6 条，数据是模拟的，对不上属于正常。
3. 滤网：第 10 条，`filter_life = 100` 指 100 天，`filter_life_p = 1` 指 100%（比例，1 = 100%）；新风机一直关机，滤网没有消耗。两个字段没有反。前端按天数和比例读（`src/features/freshAir/filter.ts`），撤掉了 `freshAirFilterSwapped` 开关。proto 里 `filter_life_p` 是 int32，按比例只能是 0 或 1，已列入待后端确认。
4. 两个测试项目共用一块屏（第 7 条），260911001 没有房间（第 14 条），读 200 返回 `{}` 是预期的。

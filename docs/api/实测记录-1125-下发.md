## 五、事故说明：11/25 00:20 的 203 传了 system_mode=0

- **经过**：第一节那条 203「全部开启」按 proto 注释把运行模式「不变」当成 `OPERATION_MODE_NONE = 0`。proto3 里 0 不上线，请求体里没有 #2，后端解出 `system_mode=0`。11/25 上午现场（唐学未）反馈这块屏的系统模式变成了「关闭」、房间都关着。**很可能就是这条 203 把系统模式写成了关闭。**后端 11/25 08:56 答复第 4 条：所有字段，「不变」一律传 -1；0 是真实值。
- **影响**：240829001 / 260911001 共用的控制屏 `667b7cc6…`。第一、二节「房间开关一直是 0」的读数，可能有一部分来自这里，而不只是没上报（第三节 09:07 的变化原因仍待现场确认）。已请后端 / 现场把系统模式恢复成原来的值。
- **修复**（PR「紧急修复：203 system_mode 不变传 -1」）：规则是 **「不变 = -1」**，含 203 的运行模式枚举（按 int32 编码，线上 10 字节，后端解出 -1）。现在「全部开启」的请求体是 `CP///////////wEQ////////////ARgBJQAAgL8=`，解码为 `system_switch=-1`、`system_mode=-1`、`room_switch=1`、`room_temp=-1`。201 / 203 / 204 / 206 一律先铺 -1 再覆盖用户改动；写入口编码后再解码检查，不是明确改动的数值为 0 一律拒发，203 运行模式为 0 一律拒发（界面没有 0 这个选项）；`checkSentRecord` 同样拒绝。
- **待后端确认**：运行模式 0 实际对应什么（是否就是「关闭」），以及 -1 是否确实按「不变」处理。确认前不做 203 改运行模式的真机测试。

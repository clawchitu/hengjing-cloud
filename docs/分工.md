## 3. 约定

1. **文件归属**：共享 hooks 和 `src/api/**` 下的读接口，Claw 可以写。`guard.ts`、写入口、写防护配置只归 Chitu。S9、S10 的下发必须走 S4 的统一写入口。
2. **下发测试**只对 260911001 和 240829001 两个项目做。下发前在群里说一声，下发前后各读一次核对，日志和截图写进 PR。
3. **评审（所有项目通用）**：两路评审，Opus 加 Codex（gpt-6.1-terra），由 PR 作者跑。评论标题用「## Opus 评审」「## Codex 评审」，通过后各发一条「Opus 审核：通过」「Codex 审核：通过」。CI 全绿后由 Chitu 做最后把关（写路径、`src/api`、会话这几处逐行看，其余抽查）再合并。Fable 只用于方案和拆分，不做代码评审。
4. **一个页面只归一个负责人**。要动公共文件，先单独开一个小 PR。截图基线按固定顺序排队，同一时间只允许一个 PR 更新：先 rebase，再用 `-g` 只重录自己那页。
5. **下发测试错开时段**：S9、S10、S12 的下发测试不同时进行。
6. **当前项目判空（S6a 约定）**：S8–S12 的页面用 `useCurrentProject()`（`src/data/org`）取当前项目，`project` 为 null 时显示空态、不发 ctrl 请求；调用写入口（`requestWrite` / `writeCtrl` / `sendUnifiedCtrls`）前也要判空。写入口接收 `{ id, code }`，S6a 的 `Project` 可以直接传进去：白名单 `writeProjectCodes` 按 `code` 比对，请求体用 `id`；`code` 为空的项目（含占位项目）会被写防护拒绝。读接口（ctrl）用 `project.id`，界面显示 `project.code`。能力判断用 `useCapabilities(project)`，项目归属用 `projectsInGroup(group, projects)`（一个项目可能属于多个集成项目），不要用 `project.groupId`。Layout 外层有 `OrgGate`：组织数据加载中、失败、没有可见项目时不渲染 Layout 和页面。
7. **写操作确认必须用 `useConfirm()`（S3a 约定）**：S9、S10、S12 等下发前的确认弹窗一律用 `src/app/feedback` 的 `useConfirm()`（签名 `(o) => Promise<boolean>`），在发起下发的那个页面组件里调用。`useApp()` 已经不再提供 `confirm`。只有 `useConfirm()` 把请求绑定到调用它的组件实例上：组件卸载（比如项目变离线、换项目时页面重挂）、路由变化（包括后退、同路径只改 query / hash）、登出或换账号、当前项目切换时，确认会同步失效，按 `false` 结算（这时会提示「页面已变化，操作已取消」）。所以拿到 `true` 之后可以直接下发，但写入口前的判空照旧要做（见第 6 条）。

# 房间温控面板：修改设定温度与节能模式（交互说明）

效果图原型：`docs/design/thermostat-edit.html`（静态，四种状态）。依据：界面改动 1123、plan-v1 负责人答复 Q5、ctrl 200/201 文档、实测记录 1124。

## 入口与布局
- 不开弹窗、不加抽屉，直接在房间卡片内修改。卡片「设定」一行由「设定温度 / 设定湿度 / 风速」改为「设定温度（可调）/ 节能模式（可调）/ 风速（只读）」，设定湿度去除。
- 卡片右上角的节能/标准标签保留，只显示面板当前值（200 读到的 `eco`），不随草稿变化。

## 控件
- 设定温度：`−  26.0°C  +` 步进器。范围与步进暂定 **16.0–30.0°C、步长 0.5°C**，后端之后会在接口里提供设定范围，前端按接口返回的范围，缺失时回退 16 / 30 / 0.5。到上下限时对应按钮禁用。
- 节能模式：开关，文字显示「标准 / 节能」，对应 `eco` 0 / 1。
- 风速：只读，显示 `wind_speed`：小于 100 为对应档位，100 为自动。

## 提交方式（推荐：同一房间合并提交）
- 点 − / + 或拨开关只改本地草稿，不立即下发。改动项高亮并显示原值，卡片底部出现「待下发：… ［取消］［下发］」。
- 一个房间一次只发一条 201，把温度和节能的改动合并。理由：每条 201 只改被修改的字段、其余一律传 -1，逐次点击逐条下发会产生多条相互覆盖的请求，连点 4 下温度就是 4 次控制屏通信。
- 单个房间不再弹二次确认，「下发」按钮本身就是确认。同一时间只允许一个房间有草稿；切到别的房间操作时，若有未下发草稿先提示放弃或下发。
- 房间开关沿用现状（即点即发），不进草稿。房间有草稿或正在下发时，开关禁用。

## 下发与结果回显
- 201 文档写的是同步等待控制屏应答后返回（读接口实测 0.7–1.9 秒，上限 10 秒），前端不用轮询。后端已确认 201 返回 `success=true` 即面板已生效。
- 下发中：本卡片所有控件禁用，底部条显示「正在下发到控制屏…」，草稿值保留。
- 成功（Reply `success=true`）：toast「主卧 已下发：设定温度 24.5°C，节能模式 开」，随即重读 200 刷新整张卡片（仅用于刷新显示，不再作为是否生效的判据）。
- 失败（HTTP 200 但 `success=false`，或 Reply 带错误文案）：卡片内红条显示后端 `msg`，草稿回退到面板当前值。
- 超时（10 秒 DeadlineExceeded）：提示「结果未知」，自动重读一次 200 核对当前值，再给「重试」按钮，不自动重试。
- 控制屏离线（503，约 0.7 秒返回）：按离线处理，见下。

## 禁用规则
- 项目离线：页面顶部黄条说明，所有可调控件和开关禁用，数值显示最后一次读取值。
- 单个面板 `is_connected=false`：该卡片禁用并标「面板离线」。
- 房间已关闭（`switch=0`）：温度与节能禁用，界面不允许设置（先开启再调）。后端虽会接受、开机后生效，但本期界面不开放。
- 与 `app_code` 无关：本页对有温控面板的项目一律可调；8 / 12 的限制只在「统一控制」里判断。

## 与 end_modes 的关系
- 末端一行按 200 的 `end_modes` 数量动态渲染：`is_selected=true` 蓝色、false 灰色，「开 / 关」取该末端的 `switch`。
- 本期末端只读。下发 201 时所有不修改的标量字段（`switch`、`humidity`、`wind_speed` 等）一律传 -1；`end_modes` 本期不改，传空列表（待联调确认）。
